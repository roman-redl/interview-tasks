# CLAUDE.md — interview-tasks

Стандарт репозитория и правила оформления задач из исходных материалов
(расшифровки собеседований, скриншоты, аудио, конспекты). Публичное описание
коллекции — в README.md; здесь — рабочий стандарт для агента.

## Структура

```
<company>/                      компания, hyphen-case латиницей (sber-auto, tochka-bank)
  README.md                     история заходов, формат собеседований, теоретические вопросы
  raid-N/                       N-й заход в компанию (не этап!): raid-2/, raid-7/…
    <stage>/                    этап внутри одного захода, определяется по содержанию
      task.md                   условия всех задач этапа
      solution/                 решения по стандарту ниже
```

- Компания с одним заходом всё равно получает `raid-1/` — структура единообразна.
- `solution/` создаётся, только если решения есть; имя — номер задачи из `task.md` и короткое название hyphen-case латиницей: `1-currying`, `2-alphabet`.
- Go-код — отдельным пакетом: `solution/N-<название>/main.go` (компилируется и запускается сам по себе); вариант решения — суффикс: `solution/N-<название>-<вариант>/main.go` (например `1-agents-pipeline-wg`). Одна задача = одна папка: решение, закрывавшее несколько задач, разносится по папкам.
- Текстовые ответы (включая «что выведется») — `solution/N-<название>.md`; SQL — `solution/N-<название>.sql`.

## Этапы (stage)

Определяются по содержанию материала, не по самоназванию собеседования:

| Папка | Что это | Признаки |
|---|---|---|
| `screening` | первичный отбор | короткое интервью, 1–2 задачи на знание языка или блиц-теория, часто прямо на созвоне с рекрутером |
| `interview` | техническое интервью | разбор опыта, серии задач, live-coding, «ты это компилятор», SQL |
| `system-design` | проектирование | «спроектируйте…», схема на экране, нагрузка, компоненты, отказоустойчивость |
| `test-task` | тестовое задание | домашнее задание с дедлайном, полный проект |
| `hr` | HR-этап | включается ТОЛЬКО если были нестандартные или странные вопросы; обычные HR-беседы не оформляются |

Повторяющиеся однотипные этапы одного захода нумеруются хронологически: `interview`, `interview-2` (пример: у Ozon raid-6 было два технических интервью — 2026-04-28 и 2026-05-07).

HR-созвон с техническим блоком — это этап `screening` и вносится в репозиторий; обычный HR-созвон без технической части не оформляется вовсе. Такой этап помечается формулировкой «скрининг на HR-созвоне» — в заголовке task.md и в таблице README захода.

## Шапка task.md

```markdown
# <Компания> — заход N, <этап по-русски>

- Даты: 2026-04-23
- Формат: онлайн, live-coding + SQL

## 1. Краткое название задачи

Условие…

```go
// код из условия дословно
```
```

- Один заход × один этап = один `task.md`, даже если было несколько сессий в разные дни (все даты в шапке).
- `task.md` не ссылается на решения и не описывает подходы — сначала самостоятельная попытка, потом `solution/`.
- Задачи нумеруются `## 1`, `## 2`… в порядке появления на собеседовании.
- Код, данные таблиц и SQL из условия переносятся дословно в код-блоки; текстовая вводная переформулируется литературно.
- В `system-design` вводная (API, нагрузка, гарантии) вносится дословно текстом
  из условия; решение в `solution/N-<название>.md` — разбор плюс диаграмма
  mermaid (GitHub рендерит) или drawio.svg.

## Правила обработки исходных материалов

1. Исходники в репозиторий не попадают никогда: расшифровки, аудио, исходные
   скрины сверх вошедших в задачи, ссылки на комнаты live-coding.
2. Анонимизация: без имён интервьюеров и рекрутеров, названий команд,
   ссылок на собеседовательные комнаты. Названия компаний остаются.
3. Условие извлекается из вопроса интервьюера, текста на экране или обсуждения
   в переписке; технические детали — дословно, формулировку — чистым языком.
   Комментарии-ответы кандидата внутри кода условия убираются — условие
   остаётся чистым тренажёром.
4. Картинки распознаются через MCP зрение: текст со скрина —
   `extract_text_from_screenshot`, схемы — `understand_technical_diagram`.
   Сложные схемы, которые инструмент не разобрал, помечаются на ручной разбор.
   Скрины созвонов в репозиторий НЕ копируются и в task.md НЕ вставляются:
   на них видны участники звонков. Дословный текст/код со скрина вносится
   вместо картинки; незаменимая схема перерисовывается (mermaid/текст).
5. Дубликаты: задача уже есть в другой компании или Common-tasks — повторно не
   добавляется. Common-tasks — для задач, встреченных в двух и более компаниях.
6. Заход ≠ этап: несколько заходов в компанию с разрывом в недели —
   разные `raid-N`; определение по календарю и датам чатов. Отсутствие
   этапа в репозитории не значит, что его не было (мог не оформляться из-за
   дублей задач).

## Гигиена репозитория

- Решения проверяются на корректность: Go-пакеты компилируются и запускаются; SQL и текстовые ответы — обоснованы.

- Язык репозитория — русский.
- Коммиты — conventional (`feat:`, `fix:`, `docs:`, `refactor:`), сообщение на
  русском, только текст, без автоподписей.
- `.idea/` и прочие IDE-файлы в git не возвращать.
- Старые имена папок с пробелами и точками (`rambler & co`, `tochka.bank`)
  не переименовываются — внешние ссылки; новые — только hyphen-case.
