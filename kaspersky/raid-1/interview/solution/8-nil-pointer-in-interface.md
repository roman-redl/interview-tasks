# Решение 8 — nil-указатель внутри интерфейса

Вывод:

```
true
true
false
```

- (1) `s == nil` — true: `s` — обычный указатель, он нулевой.
- (2) `i == nil` — true: интерфейс только объявлен, в нём ничего нет.
- (3) `i == nil` — false: при `i = s` в интерфейс записывается пара
  «динамический тип `*string` + значение nil». Сравнение `i == nil` требует,
  чтобы обе части интерфейса были нулевыми, а здесь заполнен тип — интерфейс
  уже не nil.

Как проверить, что внутри интерфейса не лежит nil-значение — сравнение с nil
не помогает, нужны другие способы:

```go
// type assertion на конкретный тип
if v, ok := i.(*string); ok && v == nil {
	fmt.Println("внутри nil-*string")
}

// или рефлексия (паникует на интерфейсах, чей тип не nilable: int, struct...)
if v := reflect.ValueOf(i); v.Kind() == reflect.Ptr && v.IsNil() {
	fmt.Println("внутри nil-указатель")
}
```

`reflect.Value.IsNil()` безопасен для указателей, слайсов, map, каналов,
функций и интерфейсов; на остальных типах паникует — отсюда проверка Kind
перед вызовом.
