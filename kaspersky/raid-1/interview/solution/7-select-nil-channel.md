# Решение 7 — select, буферный канал и nil-канал

Вывод:

```
3
2
1
```

Разбор по итерациям цикла — `select` выбирает кейс по готовности, а не по
порядку в коде; `default` берётся, только когда готовых кейсов нет:

- Итерация 1: канал `c` пуст (приём блокируется), но буфер свободен — готова
  отправка. Выполняется `case c <- 1`, печатается `3`.
- Итерация 2: в буфере лежит 1 — приём готов, отправка блокируется (буфер
  полон). Выполняется `case <-c`, печатается `2`, канал заменяется на `nil`.
- Итерация 3: `c` — nil-канал. Операции с nil-каналом блокируются навсегда,
  то есть ни один кейс не готов — срабатывает `default`: печатается `1`,
  `done = true`, цикл завершается.

Ключевая идея приёма: присваивание `c = nil` внутри обработчика —
распространённый способ «выключить» кейс из `select` в цикле, потому что
заблокированный навсегда кейс никогда не выбирается.
