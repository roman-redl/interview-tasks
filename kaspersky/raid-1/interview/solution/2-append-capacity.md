# Решение 2 — append и capacity

Вывод исходного кода (cap = 3):

```
elements are not euqal
```

После `append(s1, 1, 2, 3)` слайс `s1` заполнен целиком: len = cap = 3. Второй
`append` не помещается в ёмкость, поэтому аллоцирует новый массив и копирует
туда данные; `s2` указывает уже на него. Запись `s2[0] = 10` меняет новый
массив, `s1[0]` остаётся 1 — сравнение даёт «not euqal» (опечатка в строке из
условия).

С `make([]int, 0, 6)`:

```
elements are equal
```

Ёмкости 6 хватает на оба `append`, реаллокации нет — `s2` пишется в тот же
backing-массив, что и `s1`, поэтому `s2[0] = 10` видно и в `s1[0]`.

Как изменить исходный код, чтобы вывелось `elements are equal`: дать слайсу
запас ёмкости до первого `append` — `s1 := make([]int, 0, 6)` (или любая
ёмкость ≥ 6). Именно общая память после `append` без реаллокации и делает
изменения взаимно видимыми.
