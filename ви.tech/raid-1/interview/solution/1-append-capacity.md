# Решение 1 — append и запас ёмкости слайса

Вывод:

```
[1 2 3] [1 2 3 5] [1 2 3 5]
```

Неожиданный момент — `b`, куда дописывали 4, печатает `[1 2 3 5]`. Разбор:

- `a := make([]int, 3, 5)` — длина 3, ёмкость 5: в backing-массиве три
  занятых значения и два свободных слота.
- `b := append(a, 4)` — ёмкости хватает, реаллокации нет: `4` пишется в
  слот 3 общего массива, `b` — заголовок len 4 над ним же. `a` остаётся
  `[1 2 3]` (её len не менялся), но слот 3 массива теперь занят четвёркой.
- `c := append(a, 5)` — снова append к **исходному** `a` (len 3): пятёрка
  пишется в **тот же слот 3**, затирая только что записанную четвёрку!
  `c` — заголовок len 4 над тем же массивом: `[1 2 3 5]`.
- Печатаются: `a` — `[1 2 3]` (len 3, слотов не видит), `b` и `c` — оба
  `[1 2 3 5]`: они смотрят на один массив, и последняя запись в слот 3
  видна обоим. Проверка backing-массива: `[1 2 3 5 0]` — слот 4 никто не
  трогал.

Мораль: append к слайсу с запасом ёмкости мутирует общую память; два
независимых «продолжения» одного слайса в пределах ёмкости перезаписывают
друг друга. Независимые ветки — только через копирование (полное
выражение среза `a[:len(a):len(a)]` обрежет cap, и следующий append
реаллоцирует).
