## 1. Сумма двух чисел

Дан массив из положительных неупорядоченных чисел первым аргументом и положительное число вторым аргументом. Написать функцию, которая возвращает true, если в массиве есть 2 числа, которые в сумме дают 2-й аргумент.

Примеры:

```go
// Input: ([10,15,3,7], 17)
// Output: true

// ([2, 2], 4)
// Output: true

// Input: ([1,2,3,4,5,6], 12)
// Output: false
```

## 2. Сервис счётчиков просмотров

Тренировочная задача по следам собеседования (условие сгенерировано по идее «сервиса по раздаче счётчика просмотров с высокой нагрузкой» из методички HR; на самом собеседовании не давалась).

Необходимо спроектировать и реализовать сервис на Go, который обрабатывает запросы на инкремент и получение счётчиков просмотров (например, просмотров страниц, постов или видеороликов). Сервис должен быть оптимизирован для работы под высокой нагрузкой (сотни тысяч или миллионы запросов в секунду), обеспечивать отказоустойчивость и масштабируемость.

Требования к сервису:

**Функциональность**

- Инкремент счётчика: сервис принимает запросы на увеличение счётчика просмотров для определённого объекта (например, страницы с идентификатором `page_id`).
- Получение счётчика: сервис отдаёт текущее значение счётчика по запросу для указанного `page_id`.
- API: REST или gRPC. Например: `POST /view/{page_id}` — инкремент счётчика, `GET /view/{page_id}` — получение текущего значения.
- Формат данных: счётчик привязан к уникальному идентификатору объекта (`page_id`), например строка или UUID.

**Производительность**

- Выдерживать высокую нагрузку (например, 100 000+ запросов в секунду).
- Минимизировать задержки (latency) при обработке запросов.
- Оптимизировать использование ресурсов (CPU, память).

**Масштабируемость**

- Горизонтальное масштабирование (работа нескольких инстансов сервиса).
- Консистентность данных при распределённой обработке (например, если счётчики хранятся в распределённой БД).

**Отказоустойчивость**

- Обработка сбоев в хранилище или сети (например, временная недоступность базы данных).
- Гарантия, что просмотры не теряются при сбоях.
- Возможность обработки временных пиков нагрузки.

**Хранилище**

- Выбор подходящего хранилища для счётчиков: in-memory (например, Redis), NoSQL (например, DynamoDB, Cassandra) или SQL (например, PostgreSQL).
- Оптимизация записи и чтения для минимизации блокировок и конкуренции.

**Точность и консистентность**

- Точность счётчиков (избежать потери просмотров или дублирования).
- Выбор между строгой консистентностью (strong consistency) и конечной (eventual consistency) для оптимизации производительности.
