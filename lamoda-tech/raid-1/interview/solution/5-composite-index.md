# Решение 5 — составной индекс: какие запросы его используют

Индекс `myIdx ON carts(sku, country, customer_id)` — B-tree по трём колонкам
в порядке их следования. Работает только по **непрерывному префиксу**
колонок: `(sku)`, `(sku, country)`, `(sku, country, customer_id)`.

```sql
SELECT * FROM carts WHERE sku = 192 AND country = 'ru';
```

Использует. Условия задают первые две колонки индекса подряд — это валидный
префикс `(sku, country)`: поиск спускается по sku, затем внутри по country,
customer_id остаётся неиспользованным (но сам индекс может отдать строки
без обращения к таблице, если planner выберет index-only scan).

```sql
SELECT * FROM carts WHERE country = 'ru' AND customer_id = 10
```

Не использует. Первая колонка индекса `sku` в запросе отсутствует — префикс
нарушен, искать по дереву не с чего: диапазон по всей первой колонке
означает чтение индекса целиком, planner предпочтёт seq scan. Порядок
условий в WHERE текстом не важен — важен порядок колонок в индексе.

Развитие: современные СУБД умеут index skip scan (MySQL 8.0.13+, Oracle,
PostgreSQL частично через uniqueness — нет) — обход по значениям
отсутствующей первой колонки, когда её кардинальность мала. Как ответ на
классический вопрос на собеседовании: «не используется, потому что нет
префикса».
