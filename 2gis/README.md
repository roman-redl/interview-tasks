## Теоретические вопросы (заход 1)

### Архитектура

- Разбиение по слоям: репозиторий и CRUD-операции; где проходит граница бизнес-логики (`checkAvailability`, уменьшение квоты).
- Инверсия зависимостей через интерфейсы; замена хранилища.

### Конкурентность и базы данных

- Потокобезопасность сервиса: мьютекс на метод репозитория против транзакции на всю операцию; гонка двух одновременных бронирований одной комнаты; как не получить отрицательную квоту.
- Уровни изоляции против блокировок; `SELECT FOR UPDATE`; на какие строки ставится блокировка.
- Transaction manager: begin/commit/rollback через замыкание, скрытие транзакции от бизнес-логики; как транзакция передаётся между вызовами репозитория.
- Гарантированная отправка письма после создания заказа: статус «отправлено» в сущности + фоновый воркер; масштабирование на множество побочных действий (по сути transactional outbox).

### HTTP

- Жизненный цикл контекста запроса во фреймворке; handler и его контекст; graceful shutdown — что происходит с текущими запросами.
