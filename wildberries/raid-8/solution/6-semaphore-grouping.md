# Решение 6 — группировка слайса с семафором

Проблемы кода по убыванию серьёзности:

1. Не компилируется: `type struct semaphore` — перепутан порядок (`type
   semaphore struct`), и поле объявлено как `chan struct{} ch` вместо
   `ch chan struct{}`. Мелочь, но на собеседовании заметить обязаны.
2. Захват переменных цикла замыканием. Горутина использует `el` и `i` из
   enclosing scope: в Go до 1.22 переменные цикла одни на все итерации, и
   горутина прочитает их уже другими — в map уедут не те ключи и индексы.
   Фикс — передавать значения параметрами: `go func(i int, el string)
   {...}(i, el)`.
3. Масштаб 10¹⁸: `map[string][]int` на все элементы не поместится в память
   ни одной машины. Под «группировкой» на таком объёме понимают либо
   внешнюю сортировку + последовательную свёртку, либо шардирование по
   ключу (hash(el) → шард) с частичными map и merge. Семафор на 5 горутин
   здесь ни при чём — ограничение степени параллелизма не решает проблему
   размера результата.
4. `wg.Add(len(abc))` сразу на весь слайс — синтаксически верно, но на
   длинных входах счётчик лучше двигать порциями, синхронно с порождением
   горутин; при переполнении на 32-битных платформах `int` от 10¹⁸
   переполнится (мелочь, но сигнал о понимании).
5. Мёртвая ветка: `if mel, ok := m[el]; ok { ... } else {...}` — `mel`
   не используется, ветки дублируют друг друга; всё сводится к
   `m[el] = append(m[el], i)` безусловно.
6. Тотальная блокировка `mu` сериализует все горутины — при ограничении в
   5 горутин это терпимо, но эффективнее: локальный map на горутину с
   финальным merge под локом, либо шардированные локи по hash(key).

Исправленная версия (скомпилирована и запущена, на входе `["a","b","a",
"c","b","a"]` даёт `map[a:[0 5 2] b:[1 4] c:[3]]` — порядок внутри слайса
недетерминирован из-за конкурентного append под общим локом; при
необходимости упорядоченности — сортировать результат):

```go
func process(abc []string) map[string][]int {
	m := make(map[string][]int)

	var mu sync.Mutex
	var wg sync.WaitGroup
	sem := NewSemaphore(5)

	wg.Add(len(abc))
	for i, el := range abc {
		sem.Acquire()
		go func(i int, el string) {
			mu.Lock()
			m[el] = append(m[el], i)
			mu.Unlock()
			wg.Done()
			sem.Release()
		}(i, el)
	}

	wg.Wait()
	return m
}

type semaphore struct {
	ch chan struct{}
}

func NewSemaphore(thr int) semaphore {
	return semaphore{ch: make(chan struct{}, thr)}
}

func (s *semaphore) Acquire() { s.ch <- struct{}{} }
func (s *semaphore) Release() { <-s.ch }
```

Семафор здесь корректно ограничивает число живых горутин: `Acquire` в теле
цикла блокирует порождение новых, пока не освободится слот; `Release` и
`wg.Done` внутри горутины освобождают слот раньше ожидания `wg.Wait`.
